# Native model and provider selection

The launcher opens the project library without starting the account service. Get started never requires sign-in. ChatGPT remains an optional connection in the library; the workspace uses the existing LUMI configuration and credentials. Leaving an in-progress browser sign-in cancels its account process, and late callbacks cannot replace the project library.

The model control below the composer and **Choose Model & Provider…** in Workspace Actions open a modeless native picker. Stop, the conversation, and inspection remain available. Provider changes retain the model typed for each provider while the picker stays open. Opening the picker automatically loads models from the selected connection. The model menu combines current, recent, and provider-reported IDs without duplicates. Choosing a listed model switches immediately and closes the picker after the runtime confirms persistence. Browsing a provider does not activate it: choose a model to switch. **Other model ID…** reveals a custom field; Return or **Switch Model** submits it once. There is no second activation or Done step. Suggestions do not establish authentication, billing, or inference entitlement.

The two active engine transports are OpenAI Codex (existing ChatGPT/API-key/OpenAI-compatible endpoint configuration) and Claude Code (existing official CLI connection). Discovery uses the existing ChatGPT catalog service, the effective API-key/compatible endpoint's `/models` route, or the Claude Code discovery bridge. It does not substitute bundled model suggestions when discovery fails. This pass does not add native API-key storage, endpoint editing, new transports, or inference-entitlement verification. API keys and compatible endpoints continue to be configured through LUMI setup. Credentials do not cross the model-selection pipe.

A selection belongs to the workspace, applies to subsequent instructions, and is restored on reopening. It does not rewrite the CLI's global defaults or another workspace's selection. Conversation context and composer drafts stay intact. Recorded instructions retain their admitted provider/model; completed replies display that model alongside their evidence state.

`model-selection-v1` negotiates support. `models.list` returns the authoritative selection, revision, bounded provider suggestions, and busy state. `models.select` validates provider/model compatibility and an optimistic revision, then serializes with instruction admission, conversation changes, and project starts. Active, queued, and cancelling work blocks changes. A stale editor must reload. Failed persistence rolls back the runtime choice and metadata; a lost acknowledgment requires reconciliation rather than automatic replay. Snapshot and model-change events repair stale presentation state.

`model-discovery-v1` separately negotiates `models.discover`. Discovery is read-only and runs outside the mutation queue. Starting a workspace and taking snapshots do not contact model catalogs. Each provider has a session-local five-minute success cache, a thirty-second failure cooldown, coalesced concurrent requests, and a ten-second deadline. **Refresh** reconciles the saved workspace selection and refreshes the selected provider catalog in one action. It preserves custom edits and never applies a model.

The picker reports the catalog source, last successful check, and limited/empty/unavailable state. A failed refresh retains the last successful list with a stale label and recovery guidance. An authoritative empty response clears previous discovered suggestions. Late responses cannot overwrite another provider's visible menu or a dismissed/reconnected picker. Disconnecting clears native discovery caches. Current, recent, and custom IDs remain usable without discovery.

Selection preserves the exact ID through engine application and workspace restart. The native path does not expand CLI shorthand or rewrite provider IDs to pinned model versions. Existing CLI alias behavior is unchanged. Provider payloads are bounded, validated, deduplicated, and stripped of control/bidirectional formatting characters in display metadata; raw provider errors are not shown. Compatible-endpoint listing uses its effective inference endpoint and credentials, rejects redirects, and limits responses to 2 MiB. The API contract follows [OpenAI's list-models endpoint](https://developers.openai.com/api/reference/resources/models/methods/list); compatible endpoints can still use exact IDs if they do not implement it.

The native account channel has independent request deadlines: completing status or cancellation cannot remove another operation's timeout. Invalid account responses fail explicitly. Project-list actions require a selected row; filtering and pinning preserve the selected identity when it remains visible. Down from search and Return in the list support deliberate keyboard activation.

Pattern references: [VS Code model selection and management](https://code.visualstudio.com/docs/agent-customization/language-models) and [JetBrains third-party and local model connections](https://www.jetbrains.com/help/ai-assistant/use-custom-models.html). These informed discoverability and separation of model choice from connection setup; the runtime's actual transport support defines the available choices.

Verification: `npm run desktop:test`, `npm run desktop:test:native`, and `npx tsc --noEmit --incremental`. New regression coverage includes initial unauthenticated navigation, invalid routes, racing revisions, active-work rejection, persistence rollback, preserved failed edits, stale callbacks, and explicit reload before retry. Native visual probes use disposable workspaces and submit no model instructions.

Local evidence for this pass is under `build/model-ux-audit/`: real-worker selection/restart/global-config isolation (`runtime-evidence.json`) and native launcher/workspace captures. No live inference or new-provider credential setup was exercised. The development bundle is ad-hoc signed; public distribution remains outside this verification.

## Follow-up recovery and switching pass

The picker is also available from Workspace → Model & Provider (Shift–Command–M). The runtime retains eight recent provider/model pairs per workspace, deduplicates them, and promotes reused choices. Recent choices appear in the same model menu as the current choice and discovered models. The native menu identifies the active model; another provider initially shows Choose a model. An unchanged custom entry has no enabled Switch action.

Refresh reconciles the confirmed revision without discarding a custom model entry. To return to the active choice, select it in the model menu. Newer runtime events update the confirmed state while retaining edits; stale or malformed catalogs cannot enable saving. Busy-state guidance is separate from persistent errors. Native validation rejects incomplete catalogs, duplicate providers, unsupported identities, malformed model IDs, and invalid numeric revisions. OpenAI connection details distinguish the selected ChatGPT/API-key strategy, a configured compatible endpoint, and missing setup without exposing credentials or claiming verified access.

If saving and rollback both fail, the runtime blocks new model changes and instruction admission. Close and reopen the workspace to recover its saved selection. Browsing remains available. Recent choices share the selection's persistence boundary, including rollback.

Conversation filtering now retains navigation/load errors after clearing a no-results search, treats whitespace as an empty query, and refuses selection callbacks while switching is disabled.

## Connection recovery and navigation pass

Model edits remain in memory for the lifetime of the workspace window, including closing the picker and reconnecting the worker. A disconnected picker stays visible and allows selecting, copying, and editing its fields. Switching requires a connected runtime and a freshly reconciled selection. Reconnection invalidates old request callbacks and reads the new worker's saved revision; it never replays a model change. A new runtime can restore an earlier durable revision without trapping the picker behind its previous revision. Unsaved model edits are not persisted across closing the workspace or quitting the app.

The picker follows the workspace appearance, stays visible when switching apps, focuses the model menu on opening (or a retained custom entry), and restores the previous workspace responder when dismissed. Focus Composer closes the picker while retaining its draft for reopening.

Workspace Actions accepts multiple search terms in any order and explicit familiar aliases: history/sessions, queue/pending instructions, sidebar, and switch/change model. Project Library, ChatGPT Connection, and a disconnected workspace's Reconnect are discoverable actions. Filtering preserves the selected matching action; an empty result cannot invoke a stale row, a dismissed palette cannot dispatch twice, and text composition retains control of Return, Escape, and arrow keys. These changes preserve the native palette and shortcut presentation. References: [Apple entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data) and [VS Code user interface](https://code.visualstudio.com/docs/editing/getting-started/userinterface).

The real-app recovery probe found that an intentional pipe close revoked readiness only after process exit and skipped connection observers. The shared runtime client now immediately revokes readiness, notifies observers once, and fails pending requests through the same boundary used for transport failure. This prevents stale recovery state across workspace surfaces. Empty conversations also suppress Jump to Latest after reconnect and resize.

Final verification for this pass: 107 native tests passed. The rebuilt development app passed strict signature verification. `build/model-reconnect-ux/confirmation/` contains the final real-worker disconnect/reconnect captures and assertions for draft retention, reconciliation, Apply availability, search aliases, empty results, composer focus, and empty-conversation navigation. Light/dark and narrow-window inspection found no layout warnings. No inference was requested; new native credential setup, physical VoiceOver acceptance, and release signing remain unverified.

## Direct selection refinement

The picker now has one provider selector, one deduplicated model selector, and one Refresh action. Listed choices save directly; Other model ID exposes the sole explicit Switch Model action for custom text, also available with Return. The previous Recent, Revert, Done, Reload, Refresh Models, and Use in This Workspace controls are consolidated. Successful saves dismiss the picker and restore workspace focus. An incompatible listed ID exposes validation and recovery instead of silently failing.

Verification: the full native suite passed 148 tests before the final narrow recovery fix; all 16 focused picker tests passed afterward. Coverage includes direct selection without confirmation, duplicate-action suppression, provider browsing without mutation, custom Return, unified refresh, duplicate IDs, failed persistence, stale callbacks, disconnect/reconnect, active-work guards, and custom entries staying visible after discovery. Packaged-app checks use isolated endpoint and Claude bridge fixtures without inference. Light/dark and compact captures verify the controls and saved-selection dismissal; live provider entitlement and physical VoiceOver testing were not exercised.
